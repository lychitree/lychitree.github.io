Homelab part 6: Pi-hole and Unbound DNS

« Back to contents

What it is

  • DNS sinkhole: answers lookups normally, returns nothing for ad/tracker/malware domains on its blocklists
  • Logs every DNS lookup on the lab network (useful later for the SOC side)
  • Status: planned, screenshots and results to come

Where it lives

  • Host: Debian LXC container on the M920s (Proxmox)
  • Network: VLAN 30 (SERVERS), static IP 10.10.30.53
  • Upstream: Unbound on the OPNsense firewall (M93p), which also resolves lab hostnames under home.arpa

How DNS flows

  • TRUSTED, SERVERS, GAME: Pi-hole, then Unbound, then the internet
  • MGMT: straight to Unbound, so admin access survives if Pi-hole goes down
  • ATTACK: no DNS, fully isolated
  • The AP doesn't hand out DNS; in AP mode it just bridges Wi-Fi onto VLAN 20
  • OPNsense's DHCP gives each VLAN its DNS server

Stopping devices from going around it

  • Some devices hardcode DNS servers like 8.8.8.8 and ignore DHCP
  • Redirect: port 53 traffic to anything other than Pi-hole gets redirected to Pi-hole
  • Block DNS over TLS: outbound port 853 blocked
  • DNS over HTTPS can't be blocked by port (uses 443); blocklists catch the common DoH providers

Testing

  • Blocked domain returns 0.0.0.0: dig doubleclick.net @10.10.30.53
  • A query sent straight to 8.8.8.8 from a lab device should still appear in Pi-hole's query log (proves the redirect works)

Known weak spot

  • Single point of failure for TRUSTED, SERVERS, GAME
  • If the container stops, those VLANs lose DNS until DHCP points back at Unbound
  • Later options: a second Pi-hole, or Unbound blocklists as a fallback
