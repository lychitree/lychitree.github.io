Homelab part 6: Pi-hole

« Back to contents

What it is

Pi-hole is a DNS sinkhole. It answers lookups normally but returns nothing for the ad, tracker, and malware domains on its blocklists. It also holds the lab's local DNS records and logs every lookup it answers, which should be useful once I get to the SOC side.

Where it lives

It runs in an LXC container on the Proxmox cluster with a fixed address on VLAN 30 (SERVERS). I set it to answer all origins so devices on other VLANs and over Tailscale can use it.

Who uses it

GAME is allowed through the firewall to Pi-hole on port 53 before the rule that blocks private ranges, so the Minecraft server can still resolve names. My phone uses Pi-hole over Tailscale through the subnet router. The rest of my tailnet stays on normal DNS on purpose, so those devices keep working when the lab is down.

Testing

A blocked domain should come back as 0.0.0.0:

dig doubleclick.net @<pihole>

Weak spot

It's a single point of failure for everything pointed at it. Down the line, I could run a second Pi-hole or set up a fallback resolver on OPNsense.
