OPNsense sits at .1 on every subnet, and Dnsmasq on OPNsense hands out DHCP from .100 to .199. The firewall, switch, Proxmox hosts, Pi-hole, and the Minecraft server all have fixed addresses.

The Proxmox cluster

The two nodes are in a cluster called homelab. Corosync has two links: link 0 runs over MGMT, and link 1 runs over a direct cable between the two nodes on 192.168.2.0/24, so either one can carry the cluster if the other goes down. Each node has a VLAN-aware vmbr0 bridge, and containers get their VLAN by tag.

For IDs, I use 100–149 for containers and Linux VMs and 150–160 for Windows and AD. There's no HA yet since that needs a third quorum vote.

Why a separate firewall

I live in a shared house, so the lab can't touch anyone else's network, and I'm on a tight budget with used hardware. I kept the firewall on its own box instead of running it as a VM. A VM firewall goes down whenever Proxmox does, and it would share a hypervisor with the attack VMs. Real networks put the perimeter firewall on its own box too.

Why Proxmox

I went with Proxmox over free ESXi because free ESXi 8.0 U3e can't get later patches without a paid entitlement, and an unpatchable hypervisor doesn't make sense for a security lab.

The M920s was $106.17 on eBay. It has VT-x/VT-d, it's quiet, it idles low, and it has a low profile PCIe x16 slot, which is where the I350-T4 went. That card was a $23 OEM Fujitsu pull. I stuck with Intel NICs because they have the best Linux and FreeBSD support, and buying an OEM pull avoids the fake I350s all over eBay.

Changes from the original plan

The first version of this page had an M93p as the firewall with the I350-T4 in it and a single Proxmox host. Since then, the firewall moved to the M700 Tiny, the I350-T4 moved into the M920s, the M720s joined as a second node, and Kali got its own M720q. I also renumbered the lab from 10.10.x.x to 10.0.x.x. The R6400v2 access point and the Dell G7 SOC node aren't part of the build anymore.
